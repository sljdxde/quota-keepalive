# QKA 发布核对清单

更新日期：2026-10-30。
范围：QKA 独立桌面应用、五页签管理界面、内置周期自动执行、自动更新与 macOS/Windows 发布结构。

## 产品闭环

- 五页签固定为：应用管理、签到管理、日志、Token 速度、设置。设置位于最后，不再提供 Agent 接入页。
- 应用管理支持多个供应商、账号登录、API Key 登录、账号启停、签到/保活独立开关、单账号立即执行、额度与历史记录。
- 签到管理按供应商折叠展示，可分别触发签到、保活和额度刷新；已进入当日终态的账号不会重复领取。
- 签到结果同时记录插件返回的本次领取额度和可读取的当前余额；额度读取失败时保留已观察到的领取额度，不伪造 0。
- 日志按定时任务、签到、保活分类，展示脱敏事件，不包含 token、uid、完整手机号、请求头或原始上游响应。
- Token 速度支持本地 Agent 会话统计、工具图标、动态称号和内置称号体系；不依赖外部 Agent 才能运行签到保活。
- 设置支持浅色/深色、毛玻璃、内置或自定义背景、开机启动、系统通知、内置周期自动执行和软件更新。

## 自动执行

- `QKA task-run` 不启动主窗口或菜单栏 UI，读取 `schedule.json` 后调用现有 `App.RunAll`。
- 默认间隔 30 分钟，可配置 5 分钟至 7 天；动作支持全部、仅签到、仅保活；使用本机时区。
- macOS 使用当前用户 LaunchAgent，`StartInterval` 周期触发并设置 `RunAtLoad=true`。
- Windows 使用当前用户 Task Scheduler，`StartWhenAvailable=true`、`WakeToRun=true`、最低权限、不请求管理员权限。
- 配置目录级跨进程锁保证手动执行与系统任务不会同时领取；北京日幂等规则保持不变。
- 删除或关闭自动执行时，先删除系统任务，再持久化关闭状态。
- 不同配置目录通过路径哈希生成独立任务 ID，不互相覆盖。

## 自动更新

- 更新只读取固定官方 `feed.json`，下载制品后校验 SHA-256，不信任镜像提供的版本或哈希。
- `scripts/build-release-feed.sh` 汇总 macOS DMG 与 Windows ZIP，生成 `feed.json` 和 `SHA256SUMS`。
- macOS 更新等待当前进程退出，挂载 DMG、替换 `.app`、启动新版本，并在替换失败时恢复旧包。
- Windows 更新要求 ZIP 制品；辅助脚本等待 QKA 退出，解压到临时目录，整目录替换，启动健康检查失败时恢复 `.qka-old` 并重启旧版。
- Windows 更新同步替换 `QKA.exe`、`QKA-cli.exe`、`adapters/`、`provider-plugins/` 与 `bun.exe`，不再把 ZIP 直接覆盖到 EXE。

## 安全与隐私

- 不收集密码、验证码或扫码内容；官方登录完成后只做只读身份验证。
- 受管凭据优先使用系统安全存储，删除账号只清理 QKA 账号、来源与受管凭据，不修改供应商自身数据。
- 禁止真实腾讯账号、真实登录文件和腾讯网络用于自动化测试；自动测试只使用 `127.0.0.1` 受控假目标。
- 发布、日志、UI、筛选后的 JSON 与调度文件不得出现 token、完整身份、请求头或原始响应。

## 真机边界

- macOS 本机可完成安装、五页签、菜单栏面板、深浅色、背景、Token 速度、内置自动执行和更新 UI 验收。
- Windows 当前只能声明代码可交叉编译、调度 XML 与安装脚本结构测试通过；真实 Windows 安装、WebView2、托盘、Task Scheduler、睡眠补跑和更新替换必须在 Windows 真机另行验收。
- 不使用真实账号时，只能声明受控假目标闭环通过，不能声明腾讯线上签到、额度刷新或保活已经完成真账号验收。

## 当前结论

代码级功能与自动化测试闭环已完成；本地安装版验收在构建后执行。Windows 真机与真实账号验收尚未执行，发布说明不得提前宣称这两项完成。
