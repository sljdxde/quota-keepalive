# QKA V1 发布核对清单

在一次性 macOS 测试档案（受控假目标、不使用真实凭据）上完成的端到端验收核对。所有结论均由 `go test` / `go vet` / `gofmt` / 交叉编译实测得到。

## 1. 四个目标应用

| 目标 | 多账号发现 | 签到 | 落库/日志 | 覆盖测试 |
|---|---|---|---|---|
| WorkBuddy CN | 是 | 是（provisional→confirmed） | 是 | TestCheckinRunSuccess、TestCheckinFailureIsolatedPerAccount |
| Qoder CN | 是 | 是（活动 id 现读现用） | 是 | TestQoderDiscoverAndCheckin |
| Qoder（国际版） | 是 | 是（不可领取如实返回） | 是 | TestIntlDiscoverAndCheckin、TestIntlIndependentFromQoderCN |
| 豆包工作 | 是 | 是（首签 +200，重复业务码） | 是 | TestDoubaoFirstCheckinSuccess、TestDoubaoRepeatReturnsBusinessCode |

- WorkBuddy CN 保活：真实模型回复才成功（TestKeepaliveSuccessWithRealReply）、空回复/伪造失败（TestKeepaliveFailsWithoutRealReply）、单日一次（TestKeepaliveOncePerDay）、签到与保活互不掩盖（TestCheckinAndKeepaliveIndependent）。
- 多账号隔离：失败、来源、额度均按账号隔离，目标间互不影响。

## 2. 宿主与计划

- 配对安全：crypto/rand token、仅存 SHA-256、constant-time 校验、三层中间件（loopback/host/origin）。
- 宿主接入：Agent 接入页展示配对/连通/最近调用/计划指引；计划由宿主保存（`PlanOwnedByHost=true`），宿主内部计划恒 not_observable（`PlanObservable=false`），不展示虚构「计划已激活」。
- 五个宿主档案：WorkBuddy/Codex/ZCode/Claude Code/OpenCode 各有配置位置/传输/凭据写入/计划指引/卸载方式；不支持 MCP 的宿主如实标注。

## 3. 用户旅程（无需宿主对话）

- 五页签：应用管理、日志、账号管理、Agent 接入、插件，全部经绑定服务渲染。
- 账号旅程：发现、官方登录添加、导入只读来源、来源优先级、逐账号开关、删除，均无密码/验证码/扫码输入。
- 失败处理：doctor_run 输出 check/verdict/detail/fix；失败账号按 doctor + 日志诊断并修复。
- 设置：声明式 schema 动态渲染、进程间排他锁、备份、原子写入。

## 4. 安全与隐私

- 无遥测：代码库检索无 telemetry/analytics/sentry/mixpanel 等上报端点。
- 脱敏：`RedactURL` 对 token/key/secret/password/auth 等参数脱敏（acceptance 测试断言）。
- 日志：一行一事件、内容无凭据、保留 30 天（logtail.Prune 实测）。
- 凭据：Keychain 优先、文件回退；Keychain 拒绝冷却；未签名适配器默认禁用、不缓存授权、不访问凭据。
- 签名市场：仅加载经 ed25519 与完整制品哈希验证的适配器；篡改效应即验签失败。

## 5. 构建与 CLI

- 构建矩阵：darwin/arm64、darwin/amd64 原生构建（Mach-O 已核验）；linux/windows 交叉编译（CGO_ENABLED=0，已产出，不承诺行为）。
- 归档：含 QKA 二进制、Bun 运行时、图标；SHA256SUMS 与 feed.json 可生成。
- autostart：LaunchAgent plist，on/off 幂等。
- CLI JSON：所有形态成功/错误输出结构稳定（`{ok,data}` / `{ok:false,error}`），已实测。

## 验证命令

```
go build ./...
go vet ./...
gofmt -l internal/ cmd/      # 无输出
go test ./...                 # 全部通过
go test -race ./internal/engine/ ./internal/market/ ./internal/devmode/ ./internal/adapterhost/
make release                  # 产出双架构归档与 SHA256SUMS
```

## 结论

核对清单全部满足，QKA V1 具备发布条件。真实凭据下的线上行为需在发布后由用户在真实账号上做一次人工确认（受控假目标无法替代真实站点）。
