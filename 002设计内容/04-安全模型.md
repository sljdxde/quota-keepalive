# 04 · 安全模型

> 状态：v1.4（2026-10-29）· 落实 NFR-2、FR-6、FR-11、FR-15、FR-16、FR-20，并说明本期安全边界。

## 凭据原则

- qka 不收集、不输入、不代理任何密码、验证码或扫码内容。添加账号只允许启动目标应用官方登录页；qka 不拥有该页面中的输入控件，也不读取用户键入/扫描的内容。
- 登录态来源分两类：
  - **导入来源**：从目标应用当前登录状态读取，永远只读，不刷新、不回写。
  - **受管来源**：用户通过目标应用官方登录建立，qka 只用 Keychain 加密保存该来源必要 token，并只按官方机制刷新。
- 官方登录“返回/关闭窗口”不等于成功。qka 必须通过只读身份接口或等价无副作用查询验证目标账号与可用动作后，才能创建受管来源。
- 导入凭据解密只发生在当前执行的内存调用链中。除受管来源必要 token 可写入 qka 专属 Keychain 加密项外，token、cookie、密钥和原始凭据不能以明文落盘、不能写日志、不能出现在 MCP 返回或菜单栏文本中。
- qka 的恢复快照与状态文件均使用 `0600`，以 tmp+rename 原子写入；文件只可含账号展示信息、状态、额度与脱敏错误。
- 用户在目标应用重新登录后，下一次账号发现应恢复导入来源的可用状态；受管来源若失效，只能提示用户重新走官方登录，不能猜测或重建会话。

## 凭据源与汇双向门控（FR-16）

隐私开关不是"少调一个接口"，而是**在每个源和每个汇同时设门**：

| 门 | 位置 | 关闭后的行为 |
|---|---|---|
| 源 | Keychain 读取、凭据文件读取、目标 App 目录扫描、账号发现 | 直接短路返回"已停用"，不发起任何系统调用 |
| 汇 | 适配器派发、`credentials.resolve` 钩子、签到/保活执行、复核、上报与遥测路径 | 拒绝进入，不产生网络请求 |
| 自有存储 | qka 的受管来源 token 与登录会话状态 | **不读不写、原样保留**；重开开关即恢复可用，不因停用而丢失 |

配套规则：

- **凭据位置 Keychain 优先、文件回退**。首次读取会触发 macOS 系统授权框：这是无法静默跨过的一次摩擦，必须由安装 skill 引导用户完成并当场用 `doctor_run` 验证（对应需求文档 §7 第 1 条）。受管来源只写 qka 专属 Keychain 项，导入来源只读目标应用已有存储。
- **授权被拒后进入冷却**（默认 10 分钟）而不是每次触发都重试，避免反复弹窗骚扰用户，也避免把拒绝当成凭据失效。
- **导入来源永不刷新**：目标应用自己刷新后，qka 只重读；不调用 refresh token、不写回目标应用文件。
- **受管来源只按官方机制刷新**：适配器声明官方刷新流程，经用户可见状态链路执行；失败即标记需重登，不尝试非官方伪造会话。
- **账号与来源分离**：删除 qka 账号只删除 qka 自己的账号/来源映射及受管凭据副本，不删除目标应用账号或数据；删除导入来源只移除引用。
- 停用一个目标应用不影响其他目标应用的门（per-目标应用 粒度，见 FR-11）。

## 官方登录流程

1. 用户在账号管理页选择“添加账号”，或通过 `accounts_manage` 发起。
2. qka 只接受适配器提供的官方入口：厂商 HTTPS 域名、签名 App deep link，或目标应用自身窗口。入口不允许任意第三方域名或本地 HTML 模拟登录。
3. 登录会话由 qka 显示为可见窗口，带目标应用和当前操作说明；不注入脚本、不读取 DOM 密码框、不截屏 OCR、不录制键盘或剪贴板。
4. 用户完成官方登录后，qka 只读取完成事件/窗口返回，再用只读身份查询验证账号；关闭页面、网络错误或无法确认账号都记为未完成。
5. 验证通过后创建受管来源，并用 qka 专属 Keychain 项加密保存必要 token；MCP、日志和面板只返回来源 id、类型、状态与脱敏展示名。
6. 登录会话有超时和用户取消路径；失败不自动轮询刷新或弹出无限登录窗口。多次发起受冷却限制。

开发者模式未签名适配器不得创建受管来源；只能使用用户当场指定的单个导入来源。该限制防止第三方插件借官方登录入口扩大凭据收集范围。

### 官方登录验收路径

1. 从账号管理页或 `accounts_manage` 发起，界面必须显示目标应用、官方域名/deep link、用途与取消入口；MCP schema 中不存在密码、验证码或扫码字段。
2. 取消/超时/关闭窗口均返回 `cancelled` 或 `pending`，不得创建来源；伪造域名、非官方跳转或无法验证身份的返回一律拒绝。
3. 在官方页完成登录后，qka 只读验证目标账号与一次无副作用能力；验证失败不保存 token。
4. 验证成功创建受管来源，面板与 MCP 只显示来源 id、类型、健康状态和脱敏名称；Keychain 中不得出现明文 token 文件。
5. 导入来源的测试必须核对目标应用原凭据文件/库未被 qka 写入，来源元数据标记为 `imported/read_only`。
6. 删除账号或来源后，目标应用仍可正常登录和使用；仅 qka 自己的来源映射与受管副本被删除。

## 效应声明与最小权限的一致性（FR-15）

- manifest 声明的 `effects` 与 `needs` 必须自洽：声明 `mutatesTarget: false` 的动作若走本体写路径，本体直接拒绝；声明 `accessesNetwork: false` 的动作不得调用 `http.fetch`。
- 效应声明属于签名内容，篡改即验签失败——防止适配器"对外说只读、实际写目标应用"。
- 声明缺失的效应位按最保守值对外暴露，并在 `doctor_run` 中列为适配器质量告警；qka 自身绝不把未知当成无副作用。

## HTTP MCP 端点：三层校验

| 层 | 规则 | 目的 |
|---|---|---|
| ① loopback | 仅监听 `127.0.0.1`，并核对实际远端地址 | 不向局域网或互联网暴露本机能力 |
| ② Host / Origin | Host 必须是预期本机端点；存在 Origin 时必须是允许的本机来源，缺失 Origin 的非浏览器 MCP 客户端按 Host 规则处理 | 防浏览器 CSRF 和 DNS rebinding |
| ③ 配对 token | 每个宿主一份独立 token；所有 MCP 工具调用必须携带 | 只允许已配对的宿主调用，且可定位与单独吊销 |

- 安装 skill 将 token 写入对应宿主的 MCP 配置；qka 自身只以私有 0600 状态保存它，日志不得打印 token 或完整配置。
- **per-宿主 token**（不是全局共享一份）：qka 按 token 区分调用方，`status` 与日志可显示"哪个宿主在调用"，某个宿主泄露时只吊销它自己的一份。这与 magpie 的 `magpie-<agent>` 后缀是同一思路。
- token 存储只保存哈希，不保存明文。
- 旋转 token 会使该宿主旧配置失效；旋转属**需预演的变更**：先给出"将改写哪个宿主配置文件、备份位置、验证方式"，skill 或 qka 重写并验证该宿主配置后才报告成功（FR-1、FR-17）。
- `qka bridge` 只负责 stdio 到 HTTP 的本机转发，不能把 token 回显到 stdout、日志或错误消息。

宿主配置的每次写入都先备份原文件、写入后做连通验证、失败即回滚（FR-1）。

配对 token 防的是**未配对调用者**和浏览器页面，并不能承诺防御已取得同一 macOS 用户文件读取权限的恶意进程；这种进程能读取宿主配置，也属于本期明确的本机信任边界之外。

## 适配器供应链与权限

- 本体只加载经 ed25519 验证的适配器制品；签名覆盖版本、manifest 和完整制品哈希，市场索引记录来源、公钥、下载地址与兼容范围。
- 默认只信任官方市场。新增来源必须由用户显式授权公钥；来源的信任范围仅限其适配器。
- manifest `needs` 是 IPC 能力白名单：未声明或超出账号/操作命名空间的凭据、HTTP、状态与日志调用一律拒绝。
- Bun 子进程隔离崩溃与生命周期，本体负责凭据生命周期、出站策略、状态写入和日志脱敏。它不是本期对恶意同用户代码的 OS 级沙箱承诺。

## 隐私开关与最小读取

- 隐私开关以目标应用为粒度。关闭后 qka 不再发现、读取或解密该目标应用的任何凭据，也不触发其适配器网络请求。
- 多账号的“执行启用”状态独立保存；关闭一个账号的签到/保活不影响同一目标应用下其他账号，也不改变目标应用级隐私开关。
- 不上传遥测；运行日志、状态和余额信息只保留在本机。

## 威胁模型

| 威胁 | 本期对策 | 边界 |
|---|---|---|
| 外部网络访问 MCP | loopback | 不支持远程控制 |
| 恶意网页代调用 | Host / Origin + 配对 token | 非浏览器客户端可无 Origin，但仍必须配对 |
| 未配对本机脚本 | 配对 token | 不覆盖能读取同用户配置的恶意程序 |
| 损坏或未知适配器 | 可信公钥、制品签名（含效应声明）、来源白名单、最小 IPC 授权 | 不承诺对已获同用户权限的恶意代码完全隔离 |
| 适配器谎报后果 | 效应声明入签名、`needs` 白名单、本体按声明拒绝越权路径 | 只能约束到 IPC 能力边界，不验证真实网络行为 |
| 凭据泄露到本机状态 | 内存使用、0600 原子状态、日志脱敏 | 目标应用自身存储不由 qka 改写 |
| 钓鱼式“官方登录” | 入口域名/deep link 白名单、适配器签名、窗口显示真实目标域、完成后再做只读身份校验 | 用户设备若已被恶意软件控制，不在本期防护范围 |
| qka 偷读登录秘密 | UI 不提供账密/验证码/扫码输入框；官方窗口不注入、不截屏、不读键盘/剪贴板；MCP schema 无 secret 字段 | 依赖 macOS 权限边界与用户验证签名来源 |
| 受管 token 被插件批量继承 | `credentials.managed` 按适配器/账号/来源最小授权；未签名插件禁止创建或刷新受管来源 | 不承诺抵御已获得同用户文件权限的恶意代码 |
| 导入来源被 qka 刷新后导致原 App 掉线 | 导入来源只读；适配器 resolve 时携带 policy，刷新调用直接被拒绝 | 目标应用自身轮换仍可能使旧导入引用失效，需重新发现 |

## 免责与条款姿态

- 仅驱动用户自己的账号在本机执行；用户需自行遵守各目标应用服务条款。
- qka 与腾讯、阿里、字节等目标应用厂商无关联；兼容名称仅用于说明支持范围。
- 账号风控、额度清零或目标应用活动规则变化由用户承担；qka 以适配器更新和明确状态提示降低、而非消除这些风险。
